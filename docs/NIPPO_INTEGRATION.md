# 日報システム連携 仕様書（在庫の自動取り込み）

日報システムから**店舗×商品ごとの在庫（棚に残っている数）**を送ると、ポータル側が販売数を自動で算出します。

```
販売数 = 納品数 −（引取 + 惣菜 + 割引 + 廃棄）− 報告された在庫
```

## 前提

**先に「どの店舗に何個入れたか」の登録が必要です。** 納品の登録がない商品に在庫を送るとエラーになります（販売数を計算する元がないため）。

ポータル側の流れ:

```
出荷・納品の登録（店舗別の納品数）
        ↓
日報システムが在庫を送信  ← この仕様書の範囲
        ↓
販売数が自動算出（棚残も更新）
        ↓
生産者へ日次メール送信
        ↓
月末締め・請求書
```

## 認証

リクエストヘッダに APIキーを入れてください。

```
X-API-KEY: <APIキー>
```

キーはポータルの **設定 → 🔗 日報システム連携** で生成・確認できます。キーを変更すると古いキーは即座に使えなくなります。

## 販売先（会社）と店舗（納品先）

ポータルは取引ごとに**販売先（会社）**と**納品先（店舗）**を分けて持っています。

| 構成 | `seller` | `location` |
|---|---|---|
| 1社が複数店舗を持つ（例：みかわ の 西店・南店） | `みかわ` | `西店` / `南店` |
| 店舗ごとに独立した取引先 | `道の駅A` | 省略可 |

**在庫は店舗ごとに数えるので、1社で複数店舗ある場合は `location` の指定が必須です。**
指定せずに送ると、複数店舗に納品がある商品はエラーになります（在庫を合算して販売数を誤るのを防ぐため）。1店舗しかない商品は省略できます。

## 1. 対象商品と現在の在庫を取得する

日報に記載してもらう対象（その店舗で販売中の商品）を取得します。

```
GET /api/external/stock?seller=みかわ
GET /api/external/stock?seller=みかわ&location=西店   ← 店舗を絞る場合
```

**レスポンス**

```json
{
  "seller": "みかわ",
  "items": [
    { "location": "西店", "product": "白瓜", "producer": "森中", "unit": "袋",
      "delivered": 10, "sold": 6, "stock": 4, "lots": 1 },
    { "location": "南店", "product": "白瓜", "producer": "森中", "unit": "袋",
      "delivered": 6, "sold": 5, "stock": 1, "lots": 1 }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `delivered` | その店舗へ納品した合計 |
| `sold` | 現在記録されている販売数 |
| `stock` | 現在の在庫（ポータル側の計算値） |
| `lots` | 納品の回数（複数回に分けて納品されている場合は2以上） |

## 2. 在庫を送信する

```
POST /api/external/stock
Content-Type: application/json
X-API-KEY: <APIキー>
```

店舗ごとに送る場合（`location` を全体で指定）:

```json
{
  "seller": "みかわ",
  "location": "西店",
  "date": "2026-11-17",
  "source": "日報システム",
  "items": [
    { "product": "白瓜", "stock": 4 },
    { "product": "茄子", "stock": 0 }
  ]
}
```

1回のリクエストに複数店舗を混ぜる場合（明細ごとに `location`）:

```json
{
  "seller": "みかわ",
  "date": "2026-11-17",
  "items": [
    { "location": "西店", "product": "白瓜", "stock": 4 },
    { "location": "南店", "product": "白瓜", "stock": 1 }
  ]
}
```

| 項目 | 必須 | 意味 |
|---|---|---|
| `seller` | ○ | 販売先（会社）の名称。ポータルの登録と一致させる |
| `location` | △ | 店舗（納品先）。1社で複数店舗ある場合は必須。明細ごとの指定が優先される |
| `date` | | 在庫を数えた日。`YYYY-MM-DD`。省略時は当日 |
| `source` | | 送信元の識別（記録用・任意） |
| `items[].product` | ○ | 商品名（商品マスタの名称と一致させる） |
| `items[].stock` | ○ | **在庫数**（0以上。KG商品は小数可） |
| `items[].location` | △ | この明細の店舗。全体の `location` を上書きする |
| `items[].producer` | | 同名商品が複数の生産者にある場合に指定 |

**レスポンス**

```json
{
  "ok": true,
  "seller": "道の駅A",
  "date": "2026-11-16",
  "summary": { "total": 2, "applied": 2, "failed": 0 },
  "results": [
    { "product": "白瓜", "producer": "森中", "date": "2026-11-16",
      "reportedStock": 4, "acceptedStock": 4, "totalSellable": 14,
      "salesBefore": 0, "salesAfter": 10, "soldThisReport": 10,
      "clamped": false,
      "lots": [
        { "transactionId": "...", "salesQty": 9, "stock": 0, "soldOut": true },
        { "transactionId": "...", "salesQty": 1, "stock": 4, "soldOut": false }
      ] }
  ],
  "errors": []
}
```

| 項目 | 意味 |
|---|---|
| `acceptedStock` | 実際に反映した在庫。`reportedStock` と異なる場合は頭打ちされた |
| `clamped` | `true` なら在庫が売れうる数を超えていた（**日報の数字を確認してください**） |
| `soldThisReport` | この送信で増えた販売数 |

## 重要な性質

**同じ日報を何度送っても二重計上しません。** 在庫は「その時点の状態」なので、通信エラー後のリトライはそのまま再送して構いません。

**日報の訂正にも追従します。** 在庫を多めに訂正して送れば販売数は減ります。

**記載がない商品は変更しません。** 書き漏れがあっても、その商品の販売数が勝手に増えることはありません。完売を記録したい場合は `stock: 0` を明示的に送ってください。

**同じ商品が複数回に分けて納品されている場合**、古い納品から売れたものとみなして販売数を割り当て、残った在庫は新しい納品に残します。日報側はロットを意識する必要はありません。

## エラーの扱い

商品ごとに成否が返ります。1件失敗しても他は反映されるため、**失敗した商品だけ再送**してください。

| HTTP | 内容 |
|---|---|
| 200 | 処理完了（`errors` が空でなければ一部失敗。`ok` が `false` になる） |
| 400 | リクエストの形式不正（`seller` 欠落、`date` の形式違いなど） |
| 401 | APIキーが未指定または不一致 |

`errors[]` に入る主なメッセージ:

| メッセージ | 対処 |
|---|---|
| 該当する販売中の納品が見つかりません | その店舗・商品の納品登録が未済。商品名・店舗名の表記ゆれも確認 |
| この商品は複数の店舗に納品されています（…） | `location` で店舗を指定してください（在庫の合算を防ぐためのエラー） |
| `YYYY-MM-DD` までの報告が反映済みのため… | より新しい日付の報告が既に反映済み。古い日付へ巻き戻す送信は拒否されます |
| stock は0以上の数値で指定してください | 在庫の値を確認 |

## 送信タイミングの推奨

1日1回、閉店後にその日の在庫をまとめて送るのが基本です。生産者への日次メールは**設定した送信時刻以降**に送られるため、**メール送信時刻より前**に送信してください（送信時刻はポータルの 設定 → 売上メール自動送信 で確認できます）。

送信に失敗した場合は、時間をおいて同じ内容を再送すれば問題ありません（冪等のため）。

## 動作確認の例

```bash
# 対象商品の確認
curl -H "X-API-KEY: $KEY" \
  "https://<ポータルのURL>/api/external/stock?seller=みかわ"

# 在庫の送信（西店）
curl -X POST -H "X-API-KEY: $KEY" -H "Content-Type: application/json" \
  -d '{"seller":"みかわ","location":"西店","date":"2026-11-17","items":[{"product":"白瓜","stock":4}]}' \
  "https://<ポータルのURL>/api/external/stock"
```
